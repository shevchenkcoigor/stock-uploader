# Adobe Stock: загрузка и метаданные

Скрипт готовит пачки картинок для Adobe Stock: проверяет JPEG, генерирует заголовки и
ключевые слова через Claude, загружает файлы по SFTP и собирает CSV с метаданными.
Состояние хранится в SQLite (`state.db`), поэтому можно запускать всё по частям и
докладывать новые файлы в ту же папку.

**Что остаётся вручную в Contributor Portal:** загрузка CSV (Uploaded Files → New → Upload CSV)
и отправка на проверку. Adobe не даёт для этого API, а автоматизация портала запрещена.

## Установка

Нужен Python 3.12.

```bash
python3 -m venv .venv
source .venv/bin/activate          # fish: source .venv/bin/activate.fish
pip install -e ".[dev]"            # зависимости берутся из pyproject.toml
```

После установки доступна команда `adobe` (без активации окружения: `.venv/bin/adobe`):

```bash
adobe <команда>                    # то же, что python -m adobe_stock.cli <команда>
```

Только для запуска, без инструментов разработки (pytest, basedpyright, ruff):
`pip install -e .`

Для `caption` нужен установленный и авторизованный Claude Code (`claude`), API-ключ не нужен.
Для `upload` нужны переменные окружения (см. ниже).

## Папки

| Папка / файл | Назначение |
|---|---|
| `images/` | Корень для ваших картинок, вложенность любая. Не попадает в git |
| `csv/` | Готовые CSV для портала. Не попадает в git |
| `state.db` | База состояния. **Единственный источник правды**, не удаляйте |
| `state_backups/` | Автоматические копии базы (последние 30) |

Все пути относительные: запускайте команды из корня проекта или задайте пути явно.

## Полный flow

```
scan  →  caption  →  upload  →  csv  →  [вручную в портале]  →  submitted
```

| # | Команда | Что делает | Где |
|---|---|---|---|
| 1 | `scan` | Находит новые JPEG, проверяет их, делит на батчи | скрипт |
| 2 | `caption` | Генерирует заголовок и ключевые слова для файлов без метаданных | скрипт |
| 2a | `review`, `approve` | Если Claude пометил картинку как рискованную по правилам Adobe, вы смотрите и решаете | скрипт + вы |
| 3 | `upload` | Загружает файлы выбранного батча по SFTP | скрипт |
| 4 | `csv N` | Собирает CSV для батча N в `csv/` | скрипт |
| 5 | Upload CSV | Применяет метаданные к загруженным файлам | портал, вручную |
| 6 | Submit | Отправка на проверку | портал, вручную |
| 7 | `submitted N` | Помечает батч как отправленный | скрипт |

Типичная сессия (с активированным окружением):

```bash
adobe scan                 # images/ → новые файлы, батчи
adobe caption              # подписи; спросит модель
adobe upload               # спросит, какой батч грузить
adobe csv 3                # csv/metadata_<дата>_batch3.csv
# в портале: Upload CSV, затем отправка на проверку
adobe submitted 3
adobe status               # проверить, что где
```

Можно докладывать новые папки с картинками в `images/` и снова запускать `scan`: уже
известные файлы пропускаются, новые уходят в новые батчи, и в CSV попадут только они.

## Команды и опции

Общая опция: `--db ПУТЬ` (по умолчанию `state.db`).

### `scan [папка]`

Рекурсивно обходит папку (по умолчанию `images/`), пропускает скрытые файлы (`._*` и т.п.).

| Опция | Значение |
|---|---|
| `папка` | корень с картинками, по умолчанию `images` |
| `--metadata ФАЙЛ.csv` | один CSV с метаданными на всё дерево. Без опции берётся `metadata.csv` рядом с каждой картинкой |
| `--batch-size N` | файлов в батче, от 1 до 20000, по умолчанию **1000** |

Что происходит с каждым файлом:

- Уже известный и не менявшийся (по размеру и времени изменения) пропускается.
- Прошёл проверки и есть строка метаданных → `pending`, попадает в батч.
- Прошёл проверки, но строки метаданных нет → `needs_metadata`, ждёт `caption`.
- Не прошёл проверки или метаданные плохие → `invalid` (причина печатается, до 30 штук). Такие файлы пересматриваются при каждом скане.
- Одинаковое имя в разных подпапках: второй файл получает уникальное имя `имя_<хэш>.jpg` (SFTP плоский).
- Побайтово такое же содержимое, как у другого файла → `invalid` (`same content as …`).
- Файл изменили после загрузки → предупреждение, повторно не грузится.

Проверки картинки: JPEG, sRGB, 4–100 Мп, до 45 МБ.

### `caption`

Подписывает файлы со статусом `needs_metadata` и сразу формирует для них батчи.
Заголовок и ключевые слова на английском. Колонки про ИИ в CSV нет: пометку Generative AI
вы ставите в портале при загрузке файлов (скрипт напоминает об этом после `csv`).

| Опция | Значение |
|---|---|
| `--model ID` | модель. **Без опции покажет список и спросит** (см. ниже) |
| `--limit N` | максимум файлов за запуск, по умолчанию 50 |
| `--per-call N` | картинок в одном вызове Claude, по умолчанию 5 |
| `--workers N` | параллельных вызовов, по умолчанию 1 |
| `--batch-size N` | размер батча, по умолчанию 1000 |

**Выбор модели.** Без `--model` в терминале появляется список; Enter берёт модель по умолчанию,
можно ввести номер или id:

```
Models:
  1: claude-haiku-5-5 - fastest and lightest on usage limits (default, good for bulk)  (default)
  2: claude-sonnet-5-5 - more accurate, uses limits faster
  3: claude-opus-5-5 - stronger still, much heavier on limits
  4: claude-fable-5-2 - most capable, heaviest on limits
Model [claude-haiku-5-5]:
```

Если запуск не из терминала (скрипт, cron) или указан `--model`, вопрос не задаётся.
Список моделей лежит в `adobe_stock/caption.py` (`MODELS`), новые добавляются туда.

Как это работает: картинки уменьшаются до 1568 px, группами уходят в Claude Code в
облегчённом режиме (без MCP, навыков и пользовательских настроек, около 7 тысяч токенов на вызов).
Работает по вашей подписке, лимиты общие. После двух подряд упавших вызовов (лимит, вход)
команда останавливается; уже подписанное сохраняется, остальное допишется при следующем запуске.

Claude выбирает также категорию Adobe: только из 21 категории (`adobe_stock/categories.py`),
и в колонку `Category` попадает числовой код (например, `7` для Food). Код вне списка отбрасывается,
колонка остаётся пустой.

Подписи и категории нужно хотя бы выборочно проверять глазами.

### `review` и `approve`

Файлы, которые Claude пометил как возможное нарушение правил Adobe для ИИ-контента (реальный
узнаваемый человек, известный персонаж, бренд или логотип, чужая работа, госорган, новостное событие),
получают статус `review` и **не попадают ни в батч, ни в загрузку**.

| Команда | Что делает |
|---|---|
| `review` | показывает такие файлы с причиной, заголовком и путём |
| `approve ИМЯ [ИМЯ…]` | выпускает указанные файлы в очередь загрузки (имена как в `review`) |
| `approve --all` | выпускает все; опция `--batch-size` как у `scan` |

Если файл вам не нужен, просто удалите или уберите его из `images/`.

### `upload`

Загружает файлы выбранного батча (статус `pending`) по SFTP в корень аккаунта.
После каждого файла статус сразу пишется в базу, поэтому прерванная загрузка продолжается с места остановки.

| Опция | Значение |
|---|---|
| `--batch N` | батч для загрузки. **Без опции покажет список батчей с ожидающими файлами и спросит** |

**Выбор батча.** В списке только батчи, где ещё есть `pending`; Enter берёт последний:

```
Batches with pending files:
  1: /…/images part 1 - 1000 files
  2: /…/images part 2 - 1000 files
  3: /…/images part 3 - 412 files  (default)
Batch to upload [3]:
```

Ввод номера, которого нет в списке, останавливает команду без загрузки. Если запуск
не из терминала, берётся последний батч.

Настройки SFTP берутся из файла `.env` или из переменных окружения (переменные окружения главнее файла).
Скопируйте образец и впишите логин и пароль:

```bash
cp .env.example .env
```

Подробнее про все настройки смотрите в разделе «Настройки» ниже.

### `csv N`

Собирает CSV батча N из загруженных (`uploaded`) и ещё не отправленных файлов.

| Опция | Значение |
|---|---|
| `N` | номер батча (смотрите в `status`) |
| `--csv-dir ПАПКА` | куда класть CSV, по умолчанию `csv/` (или `ADOBE_CSV_DIR`) |
| `--output ФАЙЛ` | явное имя файла вместо автоматического |

Имя: `csv/metadata_<дата>_batch<N>.csv`. Путь запоминается в базе, и повторный `csv N`
**перезаписывает тот же файл**. Колонки CSV: `Filename`, `Title`, `Keywords`, `Category`, `Releases` (как в образце Adobe;
`Releases` остаётся пустой). Лимиты: до 20 000 строк и 20 МБ, UTF-8. После записи файл
проверяется повторно: заголовки, число колонок, имена файлов, размер и кодировка.

### `submitted N`

Вы запускаете после отправки батча на проверку в портале: файлы получают статус `submitted` и
больше не попадают в CSV. Предупредит, если у батча не было CSV.

### `log`

История действий хранится в таблице `events` в `state.db` (попадает в бэкапы вместе с базой) и никогда
не перезаписывается. Пишутся: итог каждого `scan`, `caption`, `upload`, `csv`, `approve`, `submitted`,
`restore`, а также отдельные события по файлам: невалидный файл, замечание Claude (`review`), ошибка
подписи, успешная и неудачная загрузка.

```bash
adobe log                        # последние 50 событий, новые внизу
adobe log --limit 200
adobe log --level error          # только ошибки (info, warning, error)
adobe log --command upload       # только загрузки
```

### `status`

Показывает батчи, связанный с каждым CSV и количество файлов по статусам:

```
batch 1: /…/images part 1, csv: /…/csv/metadata_2026-11-20_batch1.csv
    uploaded: 1000
batch 2: /…/images part 2, csv: -
    pending: 1000
no batch (invalid or waiting for metadata)
    needs_metadata: 12
    invalid: 3
```

### `restore [--force]`

Восстанавливает `state.db` из последнего валидного бэкапа. Если `state.db` существует,
нужен `--force` (старый файл переименуется в `state.db.replaced`).

## Настройки

Настройки описаны pydantic-моделью `Settings` (`adobe_stock/settings.py`). Каждое поле читается
из переменной `ADOBE_<ИМЯ>` в окружении или из файла `.env` в текущей папке; окружение главнее.
Неверные значения (например, порт не числом или вне 1–65535) дают понятную ошибку.
`.env` в `.gitignore`; в git лежит только образец `.env.example`.

| Переменная | Нужна | Значение |
|---|---|---|
| `ADOBE_SFTP_USER` | для `upload` | логин SFTP |
| `ADOBE_SFTP_PASSWORD` | для `upload` | пароль SFTP (в логах и `repr` скрыт) |
| `ADOBE_SFTP_HOST` | нет | по умолчанию `sftp.contributor.adobestock.com` |
| `ADOBE_SFTP_PORT` | нет | по умолчанию 22 |
| `ADOBE_BACKUP_DIR` | нет | папка бэкапов, по умолчанию `<имя базы>_backups` рядом с базой |
| `ADOBE_CSV_DIR` | нет | папка для CSV, по умолчанию `csv` |
| `ADOBE_AI_TITLE_LABEL` | нет | текст в конце каждого заголовка в CSV, по умолчанию `Generative AI`; пустое значение (`ADOBE_AI_TITLE_LABEL=`) отключает |

## Правила Adobe для ИИ-контента

Источник: Adobe «Generative AI content guidelines» (обновлено 2026-06-11). Что делает скрипт и что
остаётся за вами:

| Правило Adobe | В скрипте |
|---|---|
| В заголовках и ключевых словах нельзя имена художников, реальных людей и вымышленных персонажей, ссылки на защищённые авторским правом произведения, госорганы, чужую интеллектуальную собственность (бренды, логотипы), описания реального новостного события | Запрещено в промпте для Claude. Если на самой картинке есть такое, файл уходит в `review` и не загружается без вашего решения. Слова про ИИ и названия ИИ-инструментов (`AI`, `generative`, `generated`, `Midjourney`, `DALL-E`, `Stable Diffusion`, `ChatGPT`, `Firefly`) Claude писать не должен: они запрещены в промпте и вырезаются из заголовка и ключевых слов |
| Слова **Generative AI** в конце заголовка | Скрипт добавляет их сам при `csv N` (настройка `ADOBE_AI_TITLE_LABEL`), заголовок укладывается в 200 символов. В базе заголовок хранится без префикса, поэтому выключение или смена текста действует задним числом. В присланном тексте справки Adobe (2026-06-11) такого требования нет и запрета тоже; правило взято из вашего указания. Если в портале окажется иначе, отключите префикс |
| Галочка **Created using generative AI tools** обязательна для всего ИИ-контента | В CSV такой колонки нет: ставите в портале вручную. Скрипт напоминает после `csv` и пишет это в чеклист |
| Галочка **People and Property are fictional**, если на картинке есть выдуманный человек или объект | Claude определяет, есть ли на картинке люди; `csv` пишет список таких файлов в чеклист. Если человек реальный и узнаваемый, Adobe требует model release |
| Тип контента (фото или иллюстрация) | Claude определяет тип; список файлов по типам лежит в чеклисте |
| Не отправлять много вариантов одного промпта и похожие итерации (спам-политика) | Скрипт ловит только побайтово одинаковые файлы. **Похожие картинки отсеивайте сами** |
| Нет прав на использованные в промпте материалы | Проверить скрипт не может, это ваша ответственность |

После `csv N` рядом с CSV создаётся чеклист `csv/metadata_<дата>_batch<N>_portal_notes.txt`: количество
файлов для галочки ИИ, список файлов для «People and Property are fictional», списки фото и иллюстраций.
Для файлов с метаданными из вашего собственного `metadata.csv` информации про людей и тип нет,
они перечислены отдельно: проверьте их сами.

Оценки Claude (люди, тип, риск) это помощь, а не гарантия. Перед отправкой на проверку
просмотрите хотя бы выборочно.

## Правила для ключевых слов

Из справки Adobe («Tips for effective titles and keywords», «Keyword tutorial»). Что делает скрипт:

| Правило | Где соблюдается |
|---|---|
| Один ключевик это одно понятие: одно слово или короткая фраза, если она называет одну вещь («arctic fox»); разные понятия не склеивать | промпт для Claude |
| Главный объект первым, слова из заголовка в первых 10 | промпт |
| Город или штат указывать вместе со страной (отдельным ключевиком) | промпт |
| Каждый ключевик один раз | промпт и очистка (дубликаты убираются) |
| Без цифр и данных о файле (`2024`, `1920 x 1080`, `jpg`, `24 mp`) | промпт и очистка; `csv` отклоняет такие ключевики |
| Запятая или точка с запятой внутри ключевика разрезала бы его в CSV | очистка делит такой ключевик на части (`London, England` даёт `london` и `england`); `csv` отклоняет, если запятая осталась |
| До 49 штук, самые важные первыми | константа `MAX_KEYWORDS`, при обрезке остаются первые |

Ключевики вроде `3d render` (цифра внутри понятия) допускаются: запрещены только ключевики из одних цифр
и данные о файле. Один язык (английский) и ориентир Adobe «15–25 штук» не менялись: мы просим 25–35.

## Формат metadata.csv

Лежит рядом с картинками (в той же папке) или один на всё дерево через `scan --metadata`.
Файлы сопоставляются по имени:

```csv
filename,title,keywords,category
a.jpg,Red apple on a table,"apple, red, fruit, table",
```

`category` необязательна и, если указана, должна быть кодом из списка Adobe (1–21). Ключевых слов до 49,
заголовок до 200 символов. Лишние колонки игнорируются.
Файлы без строки в этом CSV можно подписать командой `caption`.

## Статусы файлов

| Статус | Значение |
|---|---|
| `needs_metadata` | картинка прошла проверки, ждёт заголовок и ключевые слова |
| `review` | подписан, но Claude заподозрил нарушение правил Adobe для ИИ-контента; в загрузку не идёт, пока вы не одобрите |
| `pending` | есть метаданные, лежит в батче, ещё не загружена |
| `uploaded` | загружена по SFTP, ждёт CSV и отправки |
| `submitted` | вы отметили, что батч отправлен на проверку |
| `invalid` | не прошла проверки (причина в выводе `scan`) |

Статуса «одобрено или отклонено Adobe» нет: узнать это скрипт не может.

## Защита базы

- Перед и после каждой команды `scan`, `caption`, `upload`, `csv`, `submitted` делается копия
  в `state_backups/` (хранятся последние 30, права только на чтение). Папку можно вынести
  на другой диск через `ADOBE_BACKUP_DIR`.
- Если `state.db` пропал, а бэкапы есть, любая команда остановится с подсказкой `restore`,
  а не создаст пустую базу и не перезальёт всё заново.
- При каждом запуске проверяется целостность базы.

## Правила работы с файлами

Скрипт ничего не копирует и не перемещает: в базе хранятся полные пути.

- До `upload` не переименовывайте, не перемещайте и не удаляйте файлы и папки, которые уже прошли `scan`.
- Если сдвинуть уже загруженный файл и снова запустить `scan`, он будет помечен как дубликат
  (`same content as …`) и повторно не загрузится.
- Новые файлы и папки в `images/` докладывайте свободно.

## Приложение с окном (PySide6)

Те же шаги в окне: **Скан → Описание (подписи и проверка) → Загрузка → CSV и отправка**, плюс «Настройки» и
«Журнал». Долгие операции идут в фоне с полосой прогресса и кнопкой «Отмена». Окно и консоль работают с
одной базой `state.db`, использовать можно и то и другое.

```bash
./install.sh                 # macOS / Linux: собирает приложение для этой ОС
install.bat                  # Windows: то же для Windows
python packaging/build.py    # то же напрямую (нужен Python 3.12+)
adobe-gui                    # запуск без сборки, из окружения (pip install -e ".[gui]")
```

Скрипт сам определяет ОС, создаёт `.venv`, ставит зависимости, запускает PyInstaller с флагами этой ОС,
один раз запускает результат как проверку и печатает путь:
- macOS: `dist/Adobe Stock Uploader.app` (запуск: `open "dist/Adobe Stock Uploader.app"`);
- Windows: папка `dist\Adobe Stock Uploader\` с `Adobe Stock Uploader.exe`;
- Linux: папка `dist/Adobe Stock Uploader/` (не проверялось).

Опции: `--zip` (архив для Windows/Linux, удобно копировать на другой компьютер), `--no-smoke` (без
проверки запуска), `--dry-run` (показать команды и ничего не делать). PyInstaller не собирает под чужую
ОС: Windows-версию нужно собирать на Windows, macOS-версию на macOS. Для пользователя собранного
приложения Python и PySide6 не нужны, только установленный и авторизованный Claude Code.

Первый запуск:
- **База.** По умолчанию создаётся новая база в `~/Library/Application Support/Adobe Stock Uploader/`.
  Чтобы работать с уже существующей, в «Настройках» выберите её файл `state.db`.
- **SFTP.** Логин, хост и порт в «Настройках»; пароль хранится в связке ключей macOS, а не в файле.
  Кнопка «Проверить SFTP» входит на сервер, ничего не загружая.
- **Claude.** Кнопка «Проверить Claude» показывает, где найден `claude` и какая версия. Приложение,
  запущенное из Finder, не видит ваш `PATH`, поэтому оно ищет `claude` в обычных местах
  (`~/.local/bin`, `/opt/homebrew/bin`, npm и т. д.); нестандартный путь можно указать вручную.
- **Папка CSV** по умолчанию `~/Library/Application Support/Adobe Stock Uploader/csv/`.

Сборка не подписана сертификатом Apple (подпись ad-hoc): на компьютере, где она собрана, запускается без
предупреждений; скачанную на другой Mac придётся открывать через «Системные настройки → Конфиденциальность
и безопасность → Всё равно открыть».

### Pre-commit

При каждом `git commit` автоматически запускаются `ruff check --fix`, `ruff format`, `basedpyright`
и `pytest`; если что-то не проходит, коммит блокируется. Автоисправления ruff попадают в рабочую
копию, их нужно добавить (`git add`) и повторить коммит. Один раз после клонирования:

```bash
pre-commit install
```

Вручную по всем файлам: `pre-commit run --all-files`. Хуки используют `.venv/bin/…` проекта, поэтому
окружение должно быть создано (см. «Установку»).
