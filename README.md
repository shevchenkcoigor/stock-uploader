# Adobe Stock: загрузка и метаданные

Приложение готовит пачки картинок для Adobe Stock: проверяет JPEG, генерирует заголовки и
ключевые слова через Claude, вшивает их в копии файлов, загружает копии по SFTP и ведёт учёт, что
в каком состоянии. Всё хранится в SQLite (`state.db`), поэтому работать можно по частям и докладывать
новые файлы в ту же папку.

**Что остаётся вручную в Contributor Portal:** выбор категории, галочки («Created using generative AI
tools», «People and Property are fictional») и отправка на проверку. У Adobe для этого нет API;
полуавтоматическое заполнение обсуждается в issue #22.

Приложение: Rust + Tauri 2 + React + TypeScript (папка `app/`).

## Установка и сборка

```bash
./install.sh                 # macOS / Linux: npm ci + tauri build
install.bat                  # Windows: то же для Windows
cd app && npm run tauri dev  # разработка с горячей перезагрузкой
```

Нужны Node 22+ и Rust (https://rustup.rs); на Linux ещё `libwebkit2gtk-4.1-dev`,
`libayatana-appindicator3-dev`, `librsvg2-dev`, `patchelf`, `libssl-dev`. Результат лежит в
`app/src-tauri/target/release/bundle/`:
- macOS: `macos/Adobe Stock Uploader.app` (запуск: `open "…/Adobe Stock Uploader.app"`) и `dmg/`;
- Windows: `msi/` и `nsis/` (не проверялось);
- Linux: `appimage/` и `deb/` (не проверялось).

Tauri не собирает под чужую ОС: Windows-версию нужно собирать на Windows, macOS-версию на macOS
(в CI собираются все три). Для пользователя собранного приложения Node и Rust не нужны, только
установленный и авторизованный Claude Code (`claude`); API-ключ не нужен.

Сборка не подписана сертификатом Apple (подпись ad-hoc): на компьютере, где она собрана, запускается без
предупреждений. Скачанный из интернета `.dmg` macOS помечает карантином и пишет «“Adobe Stock Uploader” is
damaged and can’t be opened» (кнопки «Всё равно открыть» в этом случае нет). Один раз после установки снимите
пометку командой:

```bash
xattr -cr "/Applications/Adobe Stock Uploader.app"
```

Обновления, которые приложение скачивает само, карантин не получают: команда нужна только после ручной установки.

## Автообновление

Приложение при запуске проверяет `latest.json` последнего GitHub Release (`plugins.updater.endpoints` в
`app/src-tauri/tauri.conf.json`). Если версия новее, вверху окна появляется баннер «Доступна версия X»;
«Обновить и перезапустить» делает бэкап `state.db`, скачивает установщик, проверяет его подпись и
перезапускает приложение. Ручная проверка: «Настройки → Обновления». Нет сети или релиза — приложение
работает как обычно. Платформы: macOS и Windows (Linux AppImage не проверялся).

Выпуск версии:
1. Поднять `version` в `app/src-tauri/tauri.conf.json` (и в `Cargo.toml`), смержить через PR.
2. `git tag vX.Y.Z && git push origin vX.Y.Z` на коммите из `main`. Воркфлоу `release.yml` проверит тег,
   прогонит те же проверки, что и CI, и соберёт подписанные установщики и `latest.json` в **черновик**
   Release. Установленные приложения черновик не видят.
3. Скачать установщик из черновика на странице Releases и проверить руками (в том числе загрузку по SFTP).
   Убедиться, что в `latest.json` есть и macOS (`darwin-aarch64`, `darwin-x86_64`), и `windows-x86_64`.
4. Опубликовать: кнопка «Publish release» или `gh release edit vX.Y.Z --draft=false --latest`. С этого
   момента приложения получают обновление. Если сборка плохая — не публиковать, а удалить черновик и тег.

Подпись обновлений — ключ minisign Tauri, не сертификат Apple/Windows. Публичный ключ лежит в
`tauri.conf.json`, приватный (`TAURI_SIGNING_PRIVATE_KEY`, пароль `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`)
хранится в GitHub Secrets и в надёжном месте вне репозитория. Потеряете его: уже установленные копии
перестанут обновляться. `latest.json` скачивается без токена, поэтому репозиторий должен оставаться
публичным (или нужен другой хостинг и новые `endpoints`).

## Первый запуск

- **База.** По умолчанию создаётся новая база в `~/Library/Application Support/Adobe Stock Uploader/`.
  Чтобы работать с уже существующей, в «Настройках» выберите её файл `state.db`.
- **SFTP.** Логин, хост и порт в «Настройках»; пароль хранится в системном хранилище (связка ключей macOS,
  Credential Manager, Secret Service), а не в файле. Кнопка «Проверить SFTP» входит на сервер, ничего не загружая.
- **Claude.** Кнопка «Проверить Claude» показывает, где найден `claude` и какая версия. Приложение,
  запущенное из Finder, не видит ваш `PATH`, поэтому оно ищет `claude` в обычных местах
  (`~/.local/bin`, `/opt/homebrew/bin`, npm и т. д.); нестандартный путь можно указать вручную.

## Папки и файлы

Рядом с `state.db` (по умолчанию `~/Library/Application Support/Adobe Stock Uploader/`):

| Папка / файл | Назначение |
|---|---|
| `state.db` | База состояния. **Единственный источник правды**, не удаляйте |
| `state_backups/` | Автоматические копии базы (последние 30) |
| `export/` | Копии картинок с вшитыми названием и ключевыми словами; именно они грузятся на SFTP |

Ваши картинки приложение не меняет, не перемещает и не удаляет.

## Полный flow

```
Скан  →  Описание  →  Загрузка  →  [вручную в портале]  →  «Отметить отправленным»
```

| # | Страница | Что делает | Где |
|---|---|---|---|
| 1 | Скан | Находит новые JPEG, проверяет их | приложение |
| 2 | Описание | Claude пишет заголовок и ключевые слова; вы правите, смотрите помеченные как рискованные и одобряете | приложение + вы |
| 3 | Загрузка | Готовит копии с вшитыми метаданными и грузит их по SFTP | приложение |
| 4 | Портал | Категория, галочки, отправка на проверку | портал, вручную |
| 5 | Загрузка | «Отметить отправленным» | приложение |

Можно докладывать новые папки с картинками и снова запускать скан: уже известные файлы пропускаются, а новые
добавляются к остальным. Страница «Загрузка» показывает все файлы сразу: те, что уже на SFTP, помечены и повторно
не грузятся (подсказка на кнопке «Загрузить» говорит, сколько файлов уйдёт и сколько пропущено).

## Что вшивается в файл

Кнопка «Загрузить» сначала готовит копию каждого файла, а потом грузит копии. Копия получает
(как её пишет Lightroom, Adobe Stock читает эти поля при загрузке):

- XMP: `dc:title`, `dc:description` (то же, что заголовок), `dc:subject` (ключевые слова);
- IPTC (UTF-8): `Headline`, `Caption-Abstract`, `Keywords` и `ObjectName`, если заголовок не длиннее 64 байт
  (это лимит поля; полный заголовок всё равно лежит в XMP и `Headline`).

Прежние XMP и IPTC в файле заменяются (например, служебный текст Midjourney в описании). Если заголовок или
ключевые слова в базе поменялись после подготовки, копия считается устаревшей и перезаписывается при
следующей загрузке; актуальные копии не трогаются. Категория и галочки ИИ в файл не вшиваются.

## Правила Adobe для ИИ-контента

Источник: Adobe «Generative AI content guidelines» (обновлено 2026-06-11). Что делает приложение и что
остаётся за вами:

| Правило Adobe | В приложении |
|---|---|
| В заголовках и ключевых словах нельзя имена художников, реальных людей и вымышленных персонажей, ссылки на защищённые авторским правом произведения, госорганы, чужую интеллектуальную собственность (бренды, логотипы), описания реального новостного события | Запрещено в промпте для Claude. Если на самой картинке есть такое, файл уходит в `review` и не загружается без вашего решения. Слова про ИИ и названия ИИ-инструментов (`AI`, `generative`, `generated`, `Midjourney`, `DALL-E`, `Stable Diffusion`, `ChatGPT`, `Firefly`) Claude писать не должен: они запрещены в промпте и вырезаются из заголовка и ключевых слов |
| Слова **Generative AI** в конце заголовка | Приложение добавляет их само сразу после ответа Claude (настройка «Метка в конце заголовка»), заголовок укладывается в 200 символов; в базе заголовок хранится уже с меткой. Проверка слов про ИИ не считает нарушением саму метку в конце (остальные AI-слова по-прежнему запрещены). В присланном тексте справки Adobe (2026-06-11) такого требования нет и запрета тоже; правило взято из вашего указания. Если в портале окажется иначе, очистите метку в «Настройках» |
| Галочка **Created using generative AI tools** обязательна для всего ИИ-контента | В файл не вшивается: ставите в портале вручную для всех файлов |
| Галочка **People and Property are fictional**, если на картинке есть выдуманный человек или объект | Claude определяет, есть ли на картинке люди, и хранит это в базе; в портале ставите вручную. Если человек реальный и узнаваемый, Adobe требует model release |
| Тип контента (фото или иллюстрация) | Claude определяет тип и хранит в базе |
| Не отправлять много вариантов одного промпта и похожие итерации (спам-политика) | Приложение ловит только побайтово одинаковые файлы. **Похожие картинки отсеивайте сами** |
| Нет прав на использованные в промпте материалы | Проверить приложение не может, это ваша ответственность |

Отдельного чеклиста для портала больше нет (раньше он создавался вместе с CSV); показ таких подсказок в
приложении относится к issue #22.

Оценки Claude (люди, тип, риск) это помощь, а не гарантия. Перед отправкой на проверку
просмотрите хотя бы выборочно.

## Правила для ключевых слов

Из справки Adobe («Tips for effective titles and keywords», «Keyword tutorial»). Что делает приложение:

| Правило | Где соблюдается |
|---|---|
| Один ключевик это одно понятие: одно слово или короткая фраза, если она называет одну вещь («arctic fox»); разные понятия не склеивать | промпт для Claude |
| Главный объект первым, слова из заголовка в первых 10 | промпт |
| Город или штат указывать вместе со страной (отдельным ключевиком) | промпт |
| Каждый ключевик один раз | промпт и очистка (дубликаты убираются) |
| Без цифр и данных о файле (`2024`, `1920 x 1080`, `jpg`, `24 mp`) | промпт и очистка; подготовка к загрузке отклоняет такие ключевики |
| Запятая или точка с запятой внутри ключевика разрезала бы его | очистка делит такой ключевик на части (`London, England` даёт `london` и `england`); подготовка отклоняет, если запятая осталась |
| До 49 штук, самые важные первыми | константа `MAX_KEYWORDS`, при обрезке остаются первые |

Ключевики вроде `3d render` (цифра внутри понятия) допускаются: запрещены только ключевики из одних цифр
и данные о файле. Один язык (английский) и ориентир Adobe «15–25 штук» не менялись: мы просим 25–35.
Заголовок не длиннее 200 символов (лимит Adobe).

## Свой metadata.csv (необязательно)

Если у вас уже есть заголовки и ключевые слова, положите `metadata.csv` рядом с картинками (в той же
папке); при скане файлы сопоставляются по имени. Это входной файл приложения, в портал он не грузится:

```csv
filename,title,keywords,category
a.jpg,Red apple on a table,"apple, red, fruit, table",
```

`category` необязательна и, если указана, должна быть кодом из списка Adobe (1–21). Ключевых слов до 49,
заголовок до 200 символов. Лишние колонки игнорируются. Файлы без строки в этом CSV описывает Claude.

## Статусы файлов

| Статус | В интерфейсе | Значение |
|---|---|---|
| `needs_metadata` | Новый | картинка прошла проверки, ждёт заголовок и ключевые слова |
| `review` | Проверить | описан, но Claude заподозрил нарушение правил Adobe для ИИ-контента; в загрузку не идёт, пока вы не одобрите |
| `pending` | Описан | есть метаданные, ещё не загружен |
| `uploaded` | На SFTP | копия загружена по SFTP, ждёт отправки в портале |
| `submitted` | Отправлен в Adobe | вы отметили, что загруженные файлы отправлены на проверку |
| `invalid` | Ошибка | не прошёл проверки (причина в журнале) |

Статуса «одобрено или отклонено Adobe» нет: узнать это приложение не может.

## Защита базы

- Перед и после каждой операции, которая меняет базу, делается копия в `state_backups/`
  (хранятся последние 30, права только на чтение). Другую папку можно задать переменной окружения
  `ADOBE_BACKUP_DIR`.
- Если `state.db` пропал, а бэкапы есть, приложение остановится с подсказкой, а не создаст пустую базу и
  не перезальёт всё заново. То же при ошибке проверки целостности. Восстановление ручное: скопируйте
  самый свежий файл из `state_backups/` на место `state.db`.

## Правила работы с файлами

В базе хранятся полные пути к вашим оригиналам, поэтому:

- до загрузки не переименовывайте, не перемещайте и не удаляйте файлы и папки, которые уже прошли скан:
  копия для загрузки делается из оригинала по сохранённому пути;
- если сдвинуть уже загруженный файл и снова запустить скан, он будет помечен как дубликат
  (`same content as …`) и повторно не загрузится;
- новые файлы и папки докладывайте свободно.

## Проверка и тесты

```bash
cd app && npm run lint && npm test && npm run build   # фронтенд: линтер, тесты, типы и сборка
cd app/src-tauri && cargo test                        # ядро на Rust
```

Коммит-хука нет: те же проверки запускает CI на каждом pull request.

## Что не проверено или не доделано

- Вшитые метаданные проверены на веб-загрузке (2026-11-22: заголовок в 167 символов и 16 ключевых слов
  подтянулись). Загрузку по SFTP на реальной партии ещё не проверяли: попробуйте сначала на 2–3 файлах.
- Хост SFTP по умолчанию и список запрещённых ключевых слов в промпте взяты по памяти, их нужно
  сверить со справкой Adobe. Список категорий (`core/categories.rs`) скопирован из справки Adobe
  2026-11-20; если Adobe его изменит, обновите файл.
- Ограничение длины имени файла Adobe не указывает; если оно есть, имена с хэшем (`имя_<хэш>.jpg`)
  могут его превысить.
- Нет повторных попыток при сетевых ошибках, восстановления базы из бэкапа в самом приложении,
  поддержки EPS/SVG. Консольной версии (`adobe`) больше нет.
