# Adobe Stock: загрузка и метаданные

Скрипт готовит пачки картинок для Adobe Stock: проверяет JPEG, генерирует заголовки и
ключевые слова через Claude, загружает файлы по SFTP и собирает CSV с метаданными.
Состояние хранится в SQLite (`state.db`), поэтому можно запускать всё по частям и
докладывать новые файлы в ту же папку.

**Что остаётся вручную в Contributor Portal:** загрузка CSV (Uploaded Files → New → Upload CSV)
и отправка на проверку. Adobe не даёт для этого API, а автоматизация портала запрещена.

## Установка

Нужен Python 3.12.

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

Дальше команды запускаются так (ниже для краткости `adobe` означает эту строку):

```bash
.venv/bin/python -m adobe_stock.cli <команда>
```

Для `caption` нужен установленный и авторизованный Claude Code (`claude`), API-ключ не нужен.
Для `upload` нужны переменные окружения (см. ниже).

## Папки

| Папка / файл | Назначение |
|---|---|
| `images/` | Корень для ваших картинок, вложенность любая. Не попадает в git |
| `csv/` | Готовые CSV для портала. Не попадает в git |
| `state.db` | База состояния. **Единственный источник правды**, не удаляйте |
| `state_backups/` | Автоматические копии базы (последние 30) |

Все пути относительные: запускайте команды из корня проекта или задайте пути явно.

## Полный flow

```
scan  →  caption  →  upload  →  csv  →  [вручную в портале]  →  submitted
```

| # | Команда | Что делает | Где |
|---|---|---|---|
| 1 | `scan` | Находит новые JPEG, проверяет их, делит на батчи | скрипт |
| 2 | `caption` | Генерирует заголовок и ключевые слова для файлов без метаданных | скрипт |
| 3 | `upload` | Загружает файлы выбранного батча по SFTP | скрипт |
| 4 | `csv N` | Собирает CSV для батча N в `csv/` | скрипт |
| 5 | Upload CSV | Применяет метаданные к загруженным файлам | портал, вручную |
| 6 | Submit | Отправка на проверку | портал, вручную |
| 7 | `submitted N` | Помечает батч как отправленный | скрипт |

Типичная сессия:

```bash
adobe scan                 # images/ → новые файлы, батчи
adobe caption              # подписи; спросит модель
adobe upload               # спросит, какой батч грузить
adobe csv 3                # csv/metadata_<дата>_batch3.csv
# в портале: Upload CSV, затем отправка на проверку
adobe submitted 3
adobe status               # проверить, что где
```

Можно докладывать новые папки с картинками в `images/` и снова запускать `scan`: уже
известные файлы пропускаются, новые уходят в новые батчи, и в CSV попадут только они.

## Команды и опции

Общая опция: `--db ПУТЬ` (по умолчанию `state.db`).

### `scan [папка]`

Рекурсивно обходит папку (по умолчанию `images/`), пропускает скрытые файлы (`._*` и т.п.).

| Опция | Значение |
|---|---|
| `папка` | корень с картинками, по умолчанию `images` |
| `--metadata ФАЙЛ.csv` | один CSV с метаданными на всё дерево. Без опции берётся `metadata.csv` рядом с каждой картинкой |
| `--batch-size N` | файлов в батче, от 1 до 5000, по умолчанию **1000** |

Что происходит с каждым файлом:

- Уже известный и не менявшийся (по размеру и времени изменения) пропускается.
- Прошёл проверки и есть строка метаданных → `pending`, попадает в батч.
- Прошёл проверки, но строки метаданных нет → `needs_metadata`, ждёт `caption`.
- Не прошёл проверки или метаданные плохие → `invalid` (причина печатается, до 30 штук). Такие файлы пересматриваются при каждом скане.
- Одинаковое имя в разных подпапках: второй файл получает уникальное имя `имя_<хэш>.jpg` (SFTP плоский).
- Побайтово такое же содержимое, как у другого файла → `invalid` (`same content as …`).
- Файл изменили после загрузки → предупреждение, повторно не грузится.

Проверки картинки: JPEG, sRGB, 4–100 Мп, до 45 МБ.

### `caption`

Подписывает файлы со статусом `needs_metadata` и сразу формирует для них батчи.
Заголовок и ключевые слова на английском. Пометка «создано ИИ» в CSV ставится всегда.

| Опция | Значение |
|---|---|
| `--model ID` | модель. **Без опции покажет список и спросит** (см. ниже) |
| `--limit N` | максимум файлов за запуск, по умолчанию 50 |
| `--per-call N` | картинок в одном вызове Claude, по умолчанию 5 |
| `--workers N` | параллельных вызовов, по умолчанию 1 |
| `--batch-size N` | размер батча, по умолчанию 1000 |

**Выбор модели.** Без `--model` в терминале появляется список; Enter берёт модель по умолчанию,
можно ввести номер или id:

```
Models:
  1: claude-haiku-5-5 - fastest and lightest on usage limits (default, good for bulk)  (default)
  2: claude-sonnet-5-5 - more accurate, uses limits faster
  3: claude-opus-5-5 - stronger still, much heavier on limits
  4: claude-fable-5-2 - most capable, heaviest on limits
Model [claude-haiku-5-5]:
```

Если запуск не из терминала (скрипт, cron) или указан `--model`, вопрос не задаётся.
Список моделей лежит в `adobe_stock/caption.py` (`MODELS`), новые добавляются туда.

Как это работает: картинки уменьшаются до 1568 px, группами уходят в Claude Code в
облегчённом режиме (без MCP, навыков и пользовательских настроек, около 7 тысяч токенов на вызов).
Работает по вашей подписке, лимиты общие. После двух подряд упавших вызовов (лимит, вход)
команда останавливается; уже подписанное сохраняется, остальное допишется при следующем запуске.

Подписи нужно хотя бы выборочно проверять глазами. Категория пока не заполняется.

### `upload`

Загружает файлы выбранного батча (статус `pending`) по SFTP в корень аккаунта.
После каждого файла статус сразу пишется в базу, поэтому прерванная загрузка продолжается с места остановки.

| Опция | Значение |
|---|---|
| `--batch N` | батч для загрузки. **Без опции покажет список батчей с ожидающими файлами и спросит** |

**Выбор батча.** В списке только батчи, где ещё есть `pending`; Enter берёт последний:

```
Batches with pending files:
  1: /…/images part 1 - 1000 files
  2: /…/images part 2 - 1000 files
  3: /…/images part 3 - 412 files  (default)
Batch to upload [3]:
```

Ввод номера, которого нет в списке, останавливает команду без загрузки. Если запуск
не из терминала, берётся последний батч.

Переменные окружения:

| Переменная | Нужна | Значение |
|---|---|---|
| `ADOBE_SFTP_USER` | да | логин SFTP |
| `ADOBE_SFTP_PASSWORD` | да | пароль SFTP |
| `ADOBE_SFTP_HOST` | нет | по умолчанию `sftp.contributor.adobestock.com` |
| `ADOBE_SFTP_PORT` | нет | по умолчанию 22 |

### `csv N`

Собирает CSV батча N из загруженных (`uploaded`) и ещё не отправленных файлов.

| Опция | Значение |
|---|---|
| `N` | номер батча (смотрите в `status`) |
| `--csv-dir ПАПКА` | куда класть CSV, по умолчанию `csv/` (или `ADOBE_CSV_DIR`) |
| `--output ФАЙЛ` | явное имя файла вместо автоматического |

Имя: `csv/metadata_<дата>_batch<N>.csv`. Путь запоминается в базе, и повторный `csv N`
**перезаписывает тот же файл**. Ограничения CSV: до 5000 строк, до 1 МБ, UTF-8.

### `submitted N`

Вы запускаете после отправки батча на проверку в портале: файлы получают статус `submitted` и
больше не попадают в CSV. Предупредит, если у батча не было CSV.

### `status`

Показывает батчи, связанный с каждым CSV и количество файлов по статусам:

```
batch 1: /…/images part 1, csv: /…/csv/metadata_2026-11-20_batch1.csv
    uploaded: 1000
batch 2: /…/images part 2, csv: -
    pending: 1000
no batch (invalid or waiting for metadata)
    needs_metadata: 12
    invalid: 3
```

### `restore [--force]`

Восстанавливает `state.db` из последнего валидного бэкапа. Если `state.db` существует,
нужен `--force` (старый файл переименуется в `state.db.replaced`).

## Формат metadata.csv

Лежит рядом с картинками (в той же папке) или один на всё дерево через `scan --metadata`.
Файлы сопоставляются по имени:

```csv
filename,title,keywords,category,ai_generated
a.jpg,Red apple on a table,"apple, red, fruit, table",,
```

`category` и `ai_generated` необязательны. Ключевых слов до 49, заголовок до 200 символов.
Файлы без строки в этом CSV можно подписать командой `caption`.

## Статусы файлов

| Статус | Значение |
|---|---|
| `needs_metadata` | картинка прошла проверки, ждёт заголовок и ключевые слова |
| `pending` | есть метаданные, лежит в батче, ещё не загружена |
| `uploaded` | загружена по SFTP, ждёт CSV и отправки |
| `submitted` | вы отметили, что батч отправлен на проверку |
| `invalid` | не прошла проверки (причина в выводе `scan`) |

Статуса «одобрено или отклонено Adobe» нет: узнать это скрипт не может.

## Защита базы

- Перед и после каждой команды `scan`, `caption`, `upload`, `csv`, `submitted` делается копия
  в `state_backups/` (хранятся последние 30, права только на чтение). Папку можно вынести
  на другой диск через `ADOBE_BACKUP_DIR`.
- Если `state.db` пропал, а бэкапы есть, любая команда остановится с подсказкой `restore`,
  а не создаст пустую базу и не перезальёт всё заново.
- При каждом запуске проверяется целостность базы.

## Правила работы с файлами

Скрипт ничего не копирует и не перемещает: в базе хранятся полные пути.

- До `upload` не переименовывайте, не перемещайте и не удаляйте файлы и папки, которые уже прошли `scan`.
- Если сдвинуть уже загруженный файл и снова запустить `scan`, он будет помечен как дубликат
  (`same content as …`) и повторно не загрузится.
- Новые файлы и папки в `images/` докладывайте свободно.

## Что не проверено или не доделано

- Заголовки колонок CSV (`HEADERS` в `adobe_stock/metadata_csv.py`) взяты по памяти. Сверьте с
  официальным шаблоном Adobe и поправьте константу.
- Название колонки AI-флага и значение `Yes` (`AI_FLAG_VALUE`) тоже не сверены с шаблоном.
- Хост SFTP по умолчанию, лимит ключевых слов (49) и список запрещённых ключевых слов в `caption`
  взяты по памяти, их нужно сверить со справкой Adobe.
- `upload` не проверялся на реальном SFTP: попробуйте сначала на 2–3 файлах.
- Нет `--dry-run`, повторных попыток при сетевых ошибках, проверки наличия файлов перед
  загрузкой, экспорта и импорта подписей для правки, поддержки EPS/SVG.
